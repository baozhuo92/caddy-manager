## 1. 核心业务流程

### 1.1 系统启动流程

```
                      应用启动
                         │
                         ▼
                ┌─ 加载配置文件 ─┐
                │  (config.yaml)  │
                └───────┬─────────┘
                        │
                        ▼
                ┌─ 初始化数据库 ─┐
                │ (自动迁移建表)  │
                └───────┬─────────┘
                        │
                        ▼
                ┌─ 检查管理员 ────┐
                │ t_user 是否有   │
                │ delete_time=0  │
                │ 的记录？        │
                └───┬───────┬─────┘
                    │       │
                存在 │       │ 不存在
                    ▼       ▼
          ┌─ 启动中间件 ─┐  ┌─ 启动中间件（拦截模式）─┐
          │ auth: 正常   │  │ auth: 放行 /init /login │
          │ init: 放行   │  │ init: 其余全部→/init    │
          └──────┬───────┘  └──────────┬──────────────┘
                 │                     │
                 ▼                     ▼
          ┌─ 启动 HTTP Server ──────────────┐
          │         监听 :8080               │
          └──────────────────────────────────┘
```

### 1.2 管理员初始化流程

```
     用户访问任意 URL（如 /）
              │
              ▼
    ┌─ init 中间件检查 ─┐
    │ t_user 表为空？   │
    └────┬───────┬──────┘
         │       │
      否 │       │ 是
         ▼       ▼
      正常   ┌──────────────┐
      放行   │ 302 → /init  │
             └──────┬───────┘
                    │
                    ▼
        ┌─ 初始化页面 (/init) ─┐
        │   输入用户名 + 密码    │
        └──────────┬───────────┘
                   │ POST /init
                   ▼
        ┌─ 验证输入 ───────────┐
        │ 用户名 4-64 字符      │
        │ 密码 6-128 字符       │
        │ 两次密码一致          │
        └──────┬───────────────┘
               │
               ▼
        ┌─ 创建管理员 ─────────┐
        │ bcrypt(password)      │
        │ INSERT t_user         │
        │ INSERT t_login_log    │
        └──────┬───────────────┘
               │
               ▼
        ┌─ 跳转 /login ───────┐
        │ 提示：管理员创建成功   │
        └──────────────────────┘
```

### 1.3 用户登录认证流程

```
     用户访问 /login?redirect=/sites
              │
              ▼
    ┌─ 登录页面 ──────────────────┐
    │  输入用户名 + 密码            │
    │  <form> 含 redirect 隐藏字段 │
    └──────────┬──────────────────┘
               │ POST /login
               ▼
    ┌─ 查询 t_user ──────────────┐
    │ username = ? AND            │
    │ delete_time = 0             │
    └──────┬─────────────────────┘
           │
   ┌───────┴────────┐
   │ 存在          │ 不存在
   ▼               ▼
┌─ bcrypt.Compare ─┐  ┌─ 返回 401 ───┐
│  密码哈希匹配？   │  │ 用户名或密码   │
└──┬───────┬───────┘  │ 错误          │
   │       │          └──────────────┘
  匹配    不匹配
   │       │
   │       ▼
   │   返回 401
   │
   ▼
┌─ 生成 Token ──────────────────┐
│ token = UUID v4               │
│ expires_at = now + 24h        │
│ INSERT t_token                │
│ INSERT t_login_log            │
└──────┬────────────────────────┘
       │
       ▼
┌─ 返回 JSON ──────────────────┐
│ {                             │
│   "token": "xxx",             │
│   "user": {                   │
│     "id": 1,                  │
│     "username": "admin"       │
│   }                           │
│ }                             │
└──────┬────────────────────────┘
       │
       ▼
  前端处理：
  1. localStorage.setItem('auth_token', token)
  2. window.location.href = redirect || '/'
```

### 1.4 Token 认证流程（中间件）

```
    前端请求
     Header: Token: xxx
              │
              ▼
    ┌─ auth 中间件 ──────┐
    │ 提取 Header.Token   │
    └──────┬──────────────┘
           │
    ┌──────┴──────────┐
    │ Token 为空？     │
    └──┬──────────┬───┘
       │          │
      是         否
       │          │
       ▼          ▼
  返回 401/   ┌─ 查 t_token ────────────────┐
  302 login   │ token = ? AND expires_at > ?   │
              │ AND delete_time = 0            │
              └──────┬─────────────────────────┘
                     │
              ┌──────┴──────────┐
              │ 找到且未过期？    │
              └──┬──────────┬───┘
                 │          │
                是         否
                 │          │
                 ▼          ▼
          ┌─ 联查 t_user ─┐  返回 401/
          │ user_id →      │  302 login
          │ gin.Context    │
          │ .Set("user")   │
          └──────┬─────────┘
                 │
                 ▼
          ┌─ c.Next() ────┐
          │ 继续后续处理    │
          └────────────────┘
```

### 1.5 前端请求拦截流程 (app.js)

```
    用户发起请求/操作
              │
              ▼
    ┌─ 从 localStorage ──┐
    │ 读取 auth_token     │
    └──────┬──────────────┘
           │
    ┌──────┴──────────┐
    │ token 存在？     │
    └──┬──────────┬───┘
       │          │
      否         是
       │          │
       ▼          ▼
   直接跳转   ┌─ 发起请求 ────────┐
   /login     │ Header: Token: xxx │
              └──────┬─────────────┘
                     │
                     ▼
              ┌─ 接收响应 ────────┐
              └──────┬────────────┘
                     │
              ┌──────┴──────────┐
              │ status == 401？ │
              └──┬──────────┬───┘
                 │          │
                是         否
                 │          │
                 ▼          ▼
          ┌─ 清除 auth_token ─┐  正常处理响应
          │ 记录 current_path  │
          │ 跳转 /login?       │
          │   redirect=path    │
          └────────────────────┘
```

### 1.6 代理站点全生命周期

```
        ┌─ 新增 ───────────────────────────────────────────────┐
        │  填写表单 → 验证数据 → INSERT t_site →                 │
        │  生成子 Caddyfile → caddy reload                      │
        └──────────────────────┬───────────────────────────────┘
                               │
                               ▼
                        ┌─ 运行中 (enabled) ─┐
                        │ Caddy 正在代理该站点 │
                        └──────┬──────┬───────┘
                               │      │
                         停用  │      │ 启用
                               ▼      ▲
                        ┌─ 已停用 (disabled) ─┐
                        │ UPDATE status        │
                        │ 删除子 Caddyfile     │
                        │ caddy reload         │
                        └──────┬───────────────┘
                               │
                         删除  │
                               ▼
                        ┌─ 已删除 (soft delete) ─┐
                        │ UPDATE delete_time      │
                        │ 删除子 Caddyfile        │
                        │ caddy reload            │
                        └─────────────────────────┘
```

### 1.7 Caddy 服务启停流程

```
    ┌─ 启动 ─────────────────────────────────────────────┐
    │  1. 检查 caddy 二进制是否存在                        │
    │  2. 确保 Caddyfile 主文件存在（不存在则根据模板创建）  │
    │  3. exec.Command("caddy", "run", "--config", path)  │
    │  4. 捕获 stdout/stderr pipe，启动日志收集协程         │
    │  5. 保存 *exec.Cmd 进程引用                          │
    └─────────────────────────────────────────────────────┘
                           │
                           ▼
                    ┌─ 运行中 ──────────┐
                    │ 协程：pipe 读日志   │
                    │ → 写入 t_caddy_log │
                    └────────┬───────────┘
                             │
                       停止  │
                             ▼
    ┌─ 停止 ──────────────────────────────────────────────┐
    │  1. cmd.Process.Signal(syscall.SIGTERM)              │
    │  2. 等待进程退出（超时 10s 则 Kill）                   │
    │  3. 关闭 pipe 并停止日志收集协程                       │
    │  4. 更新状态                                         │
    └──────────────────────────────────────────────────────┘
                             │
                             ▼
                    ┌─ 已停止 ────────────┐
                    │ 进程引用置 nil        │
                    └──────────────────────┘
```

## 3. 领域模型

### 3.1 实体关系

```
    ┌──────────┐                   ┌──────────┐
    │  t_user  │                   │ t_token  │
    │          │ 1 ────────── n    │          │
    │ 管理员   │                   │ 登录令牌 │
    └────┬─────┘                   └──────────┘
         │
         │ 1
         │
         │ n
    ┌────┴──────┐
    │ t_login_  │
    │   log     │
    │ 登录记录   │
    └───────────┘


    ┌──────────┐
    │ t_site   │                   ┌──────────────┐
    │          │                   │  子 Caddyfile │
    │ 代理站点 │ 1 ──────── 1      │  sites/xxx   │
    └──────────┘                   │   .conf       │
                                   └──────────────┘


    ┌──────────────┐
    │  t_config    │
    │  系统配置     │
    │  （K-V 存储） │
    └──────────────┘


    ┌──────────────┐
    │ t_caddy_log  │
    │ Caddy 运行   │
    │    日志      │
    └──────────────┘
```

### 3.2 t_site 字段与 Caddyfile 指令映射

| 表单字段 | t_site 字段 | Caddyfile 对应指令 |
|----------|------------|-------------------|
| 域名 | domain | `example.com { ... }` |
| 协议 | scheme | `http://` 时无自动 HTTPS，`https://`（默认）自动申请证书 |
| 代理地址 | proxy_to | `reverse_proxy http://backend:8080` |
| 请求头 | request_headers (JSON) | `header_up X-Custom Value` |
| 压缩 | compression | `encode gzip`（勾选时输出） |
| 分地址代理 | path_routes (JSON) | `handle_path /api* { reverse_proxy ... }` |
| 自定义配置 | extra_config | 原样输出到 Caddyfile |

### 3.3 request_headers JSON 格式

```json
[
  { "name": "X-Real-IP", "value": "{remote_host}" },
  { "name": "X-Forwarded-For", "value": "{remote_host}" },
  { "name": "X-Forwarded-Proto", "value": "https" }
]
```

### 3.4 path_routes JSON 格式

```json
[
  { "path": "/api", "to": "http://api-backend:3000" },
  { "path": "/ws", "to": "http://websocket:4000" }
]
```

## 4. 业务规则

### BR1: 管理员规则
- BR1.1：系统中永远只有一个管理员（login 表中 delete_time=0 的唯一记录）
- BR1.2：用户名 4-64 字符，不允许纯空格
- BR1.3：密码 6-128 字符
- BR1.4：初始化时需确认密码（两次输入一致）
- BR1.5：密码使用 bcrypt cost=12 进行哈希

### BR2: Token 规则
- BR2.1：Token 使用 UUID v4 生成
- BR2.2：有效期 24 小时（可配置）
- BR2.3：同一用户可以拥有多个 Token（多设备登录）
- BR2.4：登出时删除对应 Token 记录（物理删除）
- BR2.5：系统启动时清理所有过期 Token

### BR3: 站点配置规则
- BR3.1：域名不可重复
- BR3.2：子配置文件命名规则：`{domain}.conf`，存入 `caddyfile_sites_dir`
- BR3.3：代理地址必须为有效的 URL 格式
- BR3.4：删除站点时同时删除对应子配置文件
- BR3.5：停用站点时删除子配置文件（下次启用时重新生成）

### BR4: Caddyfile 生成规则
- BR4.1：每个站点生成独立子文件，不在主 Caddyfile 内联配置
- BR4.2：子文件头部包含自动生成标识注释
- BR4.3：主 Caddyfile 包含 `import sites/*.conf` 指令
- BR4.4：请求头中支持 Caddy 内置变量（如 `{remote_host}`、`{scheme}`）
- BR4.5：分地址代理使用 `handle_path` 指令，放在 `reverse_proxy` 之前

### BR5: Caddy 服务规则
- BR5.1：启动前检查 Caddyfile 语法（`caddy validate --config <path>`）
- BR5.2：同一时间只能有一个 Caddy 进程运行
- BR5.3：reload 操作通过 `caddy reload` 命令执行，不重启进程
- BR5.4：日志写入数据库时做批量插入（每 500ms 或满 50 条刷一次）

### BR6: 日志清理规则
- BR6.1：t_caddy_log 保留最近 10000 条记录
- BR6.2：t_login_log 保留最近 1000 条记录
- BR6.3：系统启动时执行一次清理，此后每 6 小时清理一次
