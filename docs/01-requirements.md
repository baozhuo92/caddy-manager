# 需求分析文档

---

## 1. 项目背景

运维人员在使用 Caddy 作为反向代理服务器时，每次新增或修改代理站点都需 SSH 登录服务器、手动编辑 Caddyfile、验证语法、执行 reload。这个过程繁琐、容易出错，且缺乏可视化的管理界面。

本项目旨在提供一个 **Web 管理面板**，让运维人员通过浏览器即可完成 Caddy 反向代理站点的全生命周期管理，降低运维门槛，减少人为配置错误。

## 2. 项目目标

| 目标 | 描述 |
|------|------|
| 降低门槛 | 无需 SSH 登录、无需记忆 Caddyfile 语法，通过表单即可配置反向代理 |
| 集中管理 | 统一管理多个代理站点，可视化查看启停状态、统计数量 |
| 安全访问 | 管理员账号密码登录，Token 认证，防止未授权操作 |
| 一键部署 | Docker 化部署，Alpine 镜像极致精简，开箱即用 |
| 配置持久 | 网站配置写入标准化 Caddyfile 子文件，与 Caddy 生态完全兼容 |

## 3. 用户角色

| 角色 | 描述 | 主要行为 |
|------|------|---------|
| **系统管理员**（唯一） | 负责 Caddy 服务器及代理站点管理的运维人员 | 初始化系统、登录管理面板、管理代理站点、控制 Caddy 服务 |

备注：本系统仅设计为单用户场景，不涉及多用户/多角色/权限分级。

## 4. 功能需求（FR）

### FR1: 系统初始化
| 编号 | 需求 |
|------|------|
| FR1.1 | 系统首次启动时，检测数据库中是否存在管理员账号 |
| FR1.2 | 若无管理员，所有 HTTP 请求强制重定向到初始化页面 (`/init`) |
| FR1.3 | 初始化页面提供用户名和密码输入表单，提交后创建管理员账号 |
| FR1.4 | 创建成功后自动跳转到登录页，初始化中间件放行所有请求 |

### FR2: 管理员认证
| 编号 | 需求 |
|------|------|
| FR2.1 | 提供登录页面，输入用户名和密码 |
| FR2.2 | 登录成功后返回 Token（24 小时有效期），前端存储到 localStorage |
| FR2.3 | 所有受保护请求（页面和 API）需在 Header 中携带 Token |
| FR2.4 | Token 无效或过期时，API 请求返回 401，页面请求重定向到登录页 |
| FR2.5 | 前端收到 401 时，自动清除 Token、记录当前页面路径、跳转登录页 |
| FR2.6 | 登录成功后，自动跳回登录前所在页面 |
| FR2.7 | 提供登出功能，清除 Token 并跳转到登录页 |

### FR3: 控制台仪表盘
| 编号 | 需求 |
|------|------|
| FR3.1 | 显示 Caddy 服务运行状态（运行中/已停止） |
| FR3.2 | 显示 Caddy 二进制文件是否存在 |
| FR3.3 | Docker 环境显示 "已预装"；非 Docker 环境提供一键下载按钮 |
| FR3.4 | 统计并显示代理网站总数（启用/停用分类统计） |
| FR3.5 | 显示系统的基本信息（版本、运行时间等） |

### FR4: Caddy 服务控制
| 编号 | 需求 |
|------|------|
| FR4.1 | 提供启动/停止 Caddy 服务的按钮 |
| FR4.2 | 提供刷新 Caddy 配置的按钮（热重载，不中断服务） |
| FR4.3 | 启动/停止/刷新操作后显示操作结果反馈 |
| FR4.4 | Caddy 运行日志实时写入数据库 |
| FR4.5 | 提供日志查看页面，支持按时间倒序分页展示 |

### FR5: 代理网站管理
| 编号 | 需求 |
|------|------|
| FR5.1 | 列表页展示所有代理站点，支持分页、搜索 |
| FR5.2 | 显示每个站点的域名、代理目标、状态（启用/停用） |
| FR5.3 | 新增代理站点：通过表单填写配置信息 |
| FR5.4 | 编辑代理站点：修改已有站点的配置 |
| FR5.5 | 删除代理站点：软删除记录 + 清理对应的 Caddyfile 子配置文件 |
| FR5.6 | 启用/停用代理站点 |

### FR6: 站点配置项
| 编号 | 需求 |
|------|------|
| FR6.1 | 配置域名（domain） |
| FR6.2 | 配置请求协议：HTTP 或 HTTPS（默认 HTTPS） |
| FR6.3 | 配置代理目标地址（proxy_to） |
| FR6.4 | 配置自定义请求头（request_headers），以 JSON 格式存储，支持多条 |
| FR6.5 | 配置是否启用压缩（compression） |
| FR6.6 | 配置分地址代理（path_routes），以 JSON 格式存储，支持多路径 → 多目标 |
| FR6.7 | 配置额外的自定义 Caddyfile 片段（extra_config），供高级用户使用 |

### FR7: Caddyfile 管理
| 编号 | 需求 |
|------|------|
| FR7.1 | 系统自动根据站点配置生成符合 Caddyfile 语法规范的子配置文件 |
| FR7.2 | 每个站点对应一个独立子文件，存放在指定目录 |
| FR7.3 | 主 Caddyfile 通过 `import` 指令引用子文件目录 |
| FR7.4 | 支持配置主 Caddyfile 路径和子文件目录路径 |
| FR7.5 | 站点配置变更后自动重新生成对应的子文件 |

### FR8: 系统配置
| 编号 | 需求 |
|------|------|
| FR8.1 | 支持配置管理工具自身的域名 |
| FR8.2 | 支持配置 Caddyfile 主文件路径 |
| FR8.3 | 支持配置 Caddyfile 子文件目录路径 |
| FR8.4 | 配置持久化存储在数据库中 |

## 5. 非功能需求（NFR）

### NFR1: 性能
| 编号 | 需求 |
|------|------|
| NFR1.1 | 页面首屏加载时间 < 2 秒（SSR 渲染） |
| NFR1.2 | API 响应时间 < 500ms |
| NFR1.3 | 日志表支持存储 10000 条日志仍可正常查询 |

### NFR2: 安全
| 编号 | 需求 |
|------|------|
| NFR2.1 | 密码使用 bcrypt 哈希存储，不存明文 |
| NFR2.2 | Token 使用 UUID 生成，24 小时自动过期 |
| NFR2.3 | 所有受保护接口必须经过 Token 验证 |
| NFR2.4 | 日志中不记录密码明文 |
| NFR2.5 | Caddy 子进程以非 root 用户运行（容器化场景按需调整） |

### NFR3: 可靠性
| 编号 | 需求 |
|------|------|
| NFR3.1 | 系统启动时自动执行数据库迁移 |
| NFR3.2 | Caddy 进程异常退出时能够被检测到并在管理页面显示状态 |
| NFR3.3 | 容器优雅退出：收到 SIGTERM 时先停止 Caddy 再退出 Go 程序 |

### NFR4: 可维护性
| 编号 | 需求 |
|------|------|
| NFR4.1 | 代码按 handler/service/database/middleware 分层组织 |
| NFR4.2 | 模板文件独立存放，支持布局继承 |
| NFR4.3 | 配置文件使用 YAML 格式，支持环境变量覆盖 |

### NFR5: 兼容性
| 编号 | 需求 |
|------|------|
| NFR5.1 | Docker 镜像基于 Alpine 3.21 |
| NFR5.2 | 生成的 Caddyfile 语法兼容 Caddy v2 |
| NFR5.3 | 浏览器兼容 Chrome/Firefox/Edge 最近 2 个主版本 |

### NFR6: UI/UX
| 编号 | 需求 |
|------|------|
| NFR6.1 | 全局使用简体中文 |
| NFR6.2 | 全局不使用 emoji 图标 |
| NFR6.3 | 全局组件间距统一（24px） |
| NFR6.4 | 主色为天青色 #5DADE2 |
| NFR6.5 | 设计风格遵循 Build（huashu-design #11）——大量留白、微妙字重对比、单强调色 |
| NFR6.6 | 所有页面覆盖四种状态：加载中/空数据/错误/正常 |
| NFR6.7 | 按钮文案使用动词，提示文案使用陈述句 |

## 6. 约束条件

| 约束 | 说明 |
|------|------|
| 技术栈 | Go + Gin + SQLite + html/template（SSR） |
| 部署方式 | Docker + Alpine，单容器运行 |
| 数据库 | SQLite，文件存储在挂载的 volume 中 |
| Caddy 版本 | Caddy v2，通过 Alpine apk 包管理器安装 |
| 网络 | 管理工具监听 8080 端口，Caddy 监听 80/443 端口 |
| 单用户 | 系统仅支持一个管理员账号，不支持多用户 |
| 单机 | 不支持集群/分布式部署 |
